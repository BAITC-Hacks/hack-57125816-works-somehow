# Irikteu - подбор специалистов и площадок для мероприятий

**Irikteu** - небольшой веб-сервис на русском языке, который помогает быстро подобрать специалиста или место для мероприятия из реального каталога.

Вместо просмотра длинного списка пользователь указывает несколько параметров - **город, дату, формат мероприятия, категорию и бюджет** - и получает **не более трёх подходящих профилей**.

Сервис не требует регистрации, оплаты, бронирования или API-ключей и работает локально даже без подключения к интернету.

---

## Идея проекта

При организации мероприятия человеку часто приходится просматривать множество вариантов и самостоятельно проверять, подходит ли специалист по городу, цене, дате и формату.

Мы решили сделать процесс проще:

> **Пользователь задаёт параметры → система проверяет каталог → показывает до 3 подходящих профилей → объясняет, почему каждый профиль подходит.**

Таким образом, пользователь сразу получает небольшой список релевантных вариантов вместо длинного каталога.

---

## Основные возможности

### Фильтрация по параметрам

Пользователь может выбрать:

- город;
- дату мероприятия;
- тип мероприятия;
- категорию специалиста или площадки;
- бюджет;
- язык;
- продолжительность.

Язык и продолжительность являются дополнительными фильтрами.

### До 3 результатов

Система показывает максимум **три подходящих профиля**.

Карточка профиля содержит:

- имя;
- категорию;
- город;
- начальную цену;
- конкретную особенность из описания профиля;
- объяснение соответствия запросу;
- информацию о происхождении данных.

### Проверка доступности

Дата проверяется по полю `busy_dates`.

Если специалист занят в выбранную дату, он не попадает в результаты.

### Проверка бюджета

Система использует начальную цену из каталога:

`price_from_kzt <= выбранный бюджет`

Цена отображается как **«от ... ₸»**, поэтому она не интерпретируется как окончательная стоимость услуги.

### Прозрачные причины

Если профиль не подходит, система может показать причину:

- занят в выбранную дату;
- цена выше бюджета;
- не подходит формат мероприятия;
- не работает с выбранным языком;
- не подходит продолжительность.

Если профиль не найден, пользователь получает объяснение, почему результатов нет.

## Данные

Основной источник данных:

`hackathon dataset anonymized .csv`

Каталог содержит:

- **66 профилей**
- **13 полей**
- **17 категорий**

Один профиль может относиться сразу к нескольким категориям.

Города в исходном каталоге:

* Алматы — 50 профилей;
* Астана — 15 профилей;
* `Зарубежье` — 1 профиль.

Мы используем исходный CSV непосредственно при каждом запуске приложения.

**Важно:** мы не добавляем случайные профили, цены или даты, которых нет в исходных данных.

## Как работает алгоритм

Сначала система проверяет корректность пользовательского запроса.

Затем кандидаты проходят последовательную фильтрацию:

1. Совпадение города.
2. Совпадение категории.
3. Проверка даты.
4. Проверка бюджета.
5. Проверка формата мероприятия.
6. Проверка языка, если он выбран.
7. Проверка продолжительности, если она выбрана.

После этого подходящие профили сортируются по:

1. начальной цене;
2. `id` профиля при одинаковой цене.

Первые три профиля отображаются пользователю.

### Почему результат всегда одинаковый?

В алгоритме нет случайного выбора.

Результат зависит только от:

- исходного CSV;
- параметров запроса.

Поэтому один и тот же запрос всегда возвращает один и тот же результат.

## AI и объяснение результатов

В текущей версии **внешний AI API не используется**.

Это сделано намеренно: основная логика подбора должна быть:

- быстрой;
- предсказуемой;
- проверяемой;
- независимой от интернета;
- основанной на реальных данных каталога.

Объяснение результата формируется из данных профиля и параметров запроса.

Для каждого профиля подготовлен файл:

`profile_facts.json`

Он содержит:

- краткую особенность профиля на казахском языке;
- исходный фрагмент описания, на котором основана эта информация.

Система дополнительно проверяет, что исходный фрагмент действительно существует в CSV.

### Возможное развитие AI

В дальнейшем AI можно использовать как дополнительный слой **после основного алгоритма** — например, для более естественного формирования объяснения.

При этом AI не должен:

 менять цену;
- менять дату доступности;
- добавлять несуществующие характеристики;
- менять `id`;
- менять порядок результатов;
- придумывать новые профили.

Таким образом, AI может улучшать представление информации, но не заменяет проверяемую логику подбора.

## Запуск

### Требования

- Python **3.9+**
- браузер

Дополнительные Python или JavaScript библиотеки устанавливать не требуется.

Не нужны:

- `pip install`;
- `npm install`;
- API-ключ;
- база данных;
- регистрация;
- платёжная система;
- интернет.

### Mac

Откройте Terminal и перейдите в папку проекта:

```bash
cd "$HOME/Downloads/Новая папка"
```

Проверьте Python:

```bash
python3 --version
```

Запустите приложение:

```bash
python3 event-match/server.py
```

После запуска откройте:

```text
http://127.0.0.1:8000
```

Если порт `8000` занят:

```bash
python3 event-match/server.py --port 8001
```

и откройте:

```text
http://127.0.0.1:8001
```

Чтобы остановить сервер:

```text
Control + C
```

## Ограничения проекта

Это демонстрационный локальный MVP.

В текущей версии отсутствуют:

- регистрация пользователей;
- личные кабинеты;
- онлайн-бронирование;
- платежи;
- сообщения между пользователем и специалистом;
- внешняя база данных;
- публикация приложения в интернете.

Эти функции не являются необходимыми для текущего сценария: задача проекта — показать **быстрый и прозрачный подбор профилей из заданного каталога**.

---

## Почему такой подход

Мы сознательно разделили систему на две части:

**1. Проверяемая логика подбора**
Работает непосредственно с исходными данными и строго проверяет условия пользователя.

**2. Объяснение результата**
Показывает пользователю конкретную причину, почему профиль соответствует запросу.

Это позволяет избежать ситуации, когда система просто показывает «похожего» специалиста без понятного объяснения.

## Демонстрационный сценарий

Для демонстрации можно использовать следующий запрос:

**Город:** Алматы
**Мероприятие:** Свадьба
**Категория:** Ведущий
**Бюджет:** 2 000 000 ₸
**Дата:** 23.09.2026

После поиска система проверяет каталог и показывает до трёх подходящих профилей.

Затем можно изменить дату на **24.09.2026** и показать, как изменение даты влияет на доступные варианты.

Также можно выбрать **Флорист** и показать сценарий с пустым результатом из-за занятых дат.

## Итог

**Irikteu** превращает длинный каталог специалистов и площадок в простой сценарий:

> **Выбери параметры → получи до 3 подходящих вариантов → пойми, почему они подходят.**

Проект использует реальные данные предоставленного каталога, имеет детерминированный алгоритм подбора и прозрачные объяснения результатов. Сервис не зависит от внешних API и готов к локальной демонстрации.
