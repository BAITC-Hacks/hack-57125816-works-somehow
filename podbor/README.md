# irikteu. — Подбор специалистов и площадок для мероприятий

Проект для HackAlem 2026. Подбирает до трёх специалистов или площадок и объясняет каждый выбор.
Работает полностью в браузере: без сервера, без ИИ и без ключей API.

## Запуск

Откройте `index.html` двойным кликом. Сборка не нужна.

Тесты логики (нужен Node.js 18+):

```bash
node --test tests/*.test.js
```

## Структура

```
index.html               Разметка страницы (только HTML)
data/catalog.js          Встроенный каталог (66 профилей) — не редактировать вручную
css/
  app.css                Базовые стили приложения
  app-refine.css         Доработка базовых стилей
  theme.css              Тема: белый/серый, Montserrat
  theme-images.css       Минималистичные иллюстрации (SVG)
js/
  core/                  ЛОГИКА (без DOM, работает и в Node)
    format.js            Деньги, даты, числа
    validation.js        Проверка запроса
    matcher.js           Фильтрация, сортировка, объяснения
  ui/                    ИНТЕРФЕЙС
    dom.js               Помощники для DOM
    results-view.js      Карточки, воронка, причины отказа
    compare-view.js      Сравнение двух дат
    demos.js             Демо-запросы
  app.js                 Точка входа: форма и события
  fx/effects.js          Анимации (загрузчик, появление, курсор, параллакс)
tests/matcher.test.js    Тесты логики
```

Скрипты подключаются обычными `<script>` в строгом порядке: data → core → ui → app → fx.
Все модули кладут свои функции в общий объект `Podbor` (`Podbor.format`, `Podbor.matcher` и т. д.).

## Распределение работы (3 участника)

| Участник | Роль | Файлы | Задачи на хакатоне |
|---|---|---|---|
| **1** | Логика и данные | `data/`, `js/core/`, `tests/` | Правила подбора, валидация, качество каталога, тесты |
| **2** | Интерфейс | `index.html`, `js/ui/`, `js/app.js` | Форма, карточки, сравнение дат, демо-сценарии, доступность |
| **3** | Дизайн и анимации | `css/`, `js/fx/` | Тема, адаптив под телефон, иллюстрации, анимации |

### Правила команды

1. Каждый меняет только свои файлы. Чужой файл — только после договорённости.
2. Связь между частями — только через `Podbor.*`. Логика (`core/`) не трогает DOM.
3. Участник 1 перед коммитом запускает тесты.
4. Участник 3 не меняет классы в разметке, не согласовав с Участником 2.
5. Одна ветка на участника: `logic`, `ui`, `design` → слияние в `main`.

### Точки соприкосновения

- **1 ↔ 2:** формат результата `matchProfiles()` (поля `status`, `cards`, `rejected`, `reason_counts`). Меняете поле — предупредите.
- **2 ↔ 3:** CSS-классы карточек и блоков (`profile-card`, `pipeline`, `diagnostics` …).
